# Sample 09: Dependency Ordering

This sample demonstrates DeepDiff DB's automatic dependency ordering for schema migrations. When tables have foreign key relationships, operations must be executed in the correct order to avoid constraint violations.

## Scenario

### Production Database (port 3315)
- `users` - Base user table
- `categories` - Product categories (self-referencing FK)
- `products` - Products with FK to categories
- `orders` - Orders with FK to users
- `order_items` - Order items with FKs to orders and products **(TO BE REMOVED)**
- `inventory` - Inventory with FK to products **(TO BE REMOVED)**
- `audit_log` - Audit log with FK to users **(TO BE REMOVED)**

### Development Database (port 3316)
- `users` - Unchanged
- `categories` - Unchanged
- `products` - Unchanged
- `orders` - Unchanged
- `shipping_addresses` - **NEW** - References users
- `reviews` - **NEW** - References users AND products
- `wishlists` - **NEW** - References users AND products
- `order_history` - **NEW** - References orders (chain: users → orders → order_history)

## What You'll See

### CREATE TABLE Ordering

When creating new tables, DeepDiff DB orders them so that referenced tables are created first:

```
Expected CREATE order:
1. shipping_addresses (only depends on users, which already exists)
2. order_history (only depends on orders, which already exists)
3. reviews (depends on users AND products, both exist)
4. wishlists (depends on users AND products, both exist)
```

The ordering ensures that when `ADD CONSTRAINT FOREIGN KEY` statements run, the referenced tables already exist.

### DROP TABLE Ordering

When dropping tables, DeepDiff DB orders them so that tables with foreign keys are dropped first:

```
Expected DROP order:
1. order_items (has FKs to orders and products)
2. inventory (has FK to products)
3. audit_log (has FK to users)
```

This prevents FK constraint violations during the DROP operations.

## Quick Start

### 1. Start the databases

```bash
cd samples/09-dependency-ordering
docker-compose up -d

# Wait for databases to be ready
sleep 15
```

### 2. Check connectivity

```bash
deepdiffdb check --config deepdiffdb.config.yaml
```

### 3. Run schema diff

```bash
deepdiffdb schema-diff --config deepdiffdb.config.yaml
```

### 4. Generate migration

```bash
deepdiffdb schema-migrate --config deepdiffdb.config.yaml
cat diff-output/schema_migration.sql
```

### 5. Cleanup

```bash
docker-compose down -v
```

## Circular Dependency Handling

If your schema has circular dependencies (A references B, B references A), DeepDiff DB will:

1. Detect the cycle during dependency analysis
2. Add a warning to the migration output
3. Place the operations in the result with a note about manual intervention

Example warning:
```sql
-- WARNING: Circular dependency detected between tables: table_a, table_b
-- Manual intervention may be required to break the cycle
```

## Key Takeaways

1. **CREATE TABLE ordering**: Tables are created in dependency order - if table A has a FK to table B, B is created first
2. **DROP TABLE ordering**: Tables with FKs are dropped first - if table A has a FK to table B, A is dropped before B
3. **FK statements last**: Foreign key constraints are added after all tables exist
4. **Automatic analysis**: No manual ordering required - DeepDiff DB analyzes the schema and determines the correct order
5. **Cycle detection**: Circular dependencies are detected and reported
